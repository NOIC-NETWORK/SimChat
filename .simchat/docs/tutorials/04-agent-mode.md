# 04 Agent 模式入门

> 本章属于「只使用」路径（A），前置：[03 配置工作目录与第一次对话](03-workspace-and-chat.md)。

## 1. 你会得到什么

一个可被激活的「AI 实例」，以及一次完整的 Agent 执行：能看到 计划 → 思考 → 工具调用 → 工具结果 → 最终答复 的时间线；遇到写文件这类操作会停下来等你批准。

```text
┌ 计划 ───────────────────────────────┐
│ 1. 用 glob 找出所有 py 文件          │
│ 2. 读其中最长的那个                  │
└─────────────────────────────────────┘
┌ 工具调用 glob {"pattern": "**/*.py"} ┐
│ ✓ 找到 12 个文件                     │
└─────────────────────────────────────┘
最终答复：……
```

## 2. 前置条件

- 服务商可用、工作目录已选（第 02、03 章）。
- 工作目录里最好有几个文本文件，方便观察工具调用。

## 3. 跟着做

### 3.1 创建并激活一个 AI 实例

1. 点顶部菜单里的「AI 实例 (E)」（快捷键 `E`）。
2. 点「+ 创建新实例」，弹窗里至少填两项：
   - **实例名称**（必填，最多 40 字，例如 `代码助手`）；
   - 确认「**Agent 能力**」开关是打开的（对应字段 `agent_capable`，说明是「允许该实例以 Agent 模式运行」，默认打开）。
   
   其余可选项：`ID（entity_id）`（Orbiter 的 `/@` 指令识别用，留空自动生成）、描述、头像、系统提示词、神经引擎预设（普通 / 工作 / 代码 / 创意 / 自定义参数 / W-Synk）、「允许高级功能」、「桌面宠物」。
3. 保存后回到实例列表，选中该卡片，点「进入选中的实例」（或双击卡片）。
4. 也可以不选实例：输入框旁的实例下拉里保持「— 直接对话 —」，或在输入框里用 `/@实例名` 点名。

> 首次打开「AI 实例」面板时，如果没有任何实例，SimChat 会自动建一个「默认实例」（`entity_id=default`），可以直接用；它不可删除，但可以编辑。

### 3.2 切到 Agent 模式

输入框左侧的模式开关默认是「对话」，点一下变成「Agent」。这个开关决定请求走哪条链路：

| 模式 | 前端调用 | 能力 |
|---|---|---|
| 对话 | `POST /api/chat` | 只读工具 + skills/automation 能力标识，写操作与 shell 不进工具清单 |
| Agent | `POST /api/agent/run` | 完整 ReAct 循环、写操作逐次审批、可中断 |

### 3.3 跑一个多步任务

发这句（把路径换成你目录里真实存在的东西）：

```text
列出工作目录下所有 .py 文件，挑一个最大的读前 40 行，告诉我它是做什么的
```

预期依次出现：计划卡片 → 若干「思考」卡片 → `glob` 工具调用卡片及结果 → `file_read` 卡片及结果 → 最终答复。整个过程不需要你点任何东西，因为 `glob`、`file_read` 都是只读级。

### 3.4 体验一次审批

再发一句：

```text
在当前目录新建 notes.md，写入三行：这是 SimChat 的测试文件
```

预期：Agent 先给出方案，然后卡在一张审批卡片上，卡片会写明工具名、风险级别、参数。点「批准」才会真正写文件；点「拒绝」后 Agent 会换思路或直接结束。

### 3.5 中断

Agent 运行时点停止按钮，前端调 `POST /api/agent/abort {run_id}`，时间线上会出现一条「⏹ 任务已中止」。停下后可以继续发新任务，上下文仍在这个会话里。

### 3.6 看工具清单（可选）

```bash
curl http://127.0.0.1:5000/api/agent/tools
```

返回每个工具的 `name / label / description / risk / usage / enabled`。`enabled=false` 的工具（例如未开启的 `shell`）前端可见但不可用。

## 4. 为什么会这样

- **实例是什么**：实例 = 地图（人设 + 引擎参数 + 能力的组合），存在 `.simchat/data/agents/<id>.json`。激活后，它的系统提示词与「神经引擎预设」的参数会随请求带给后端；`agent_capable=false` 的实例不能跑 Agent。
- **一次 Agent 回合做了什么**：`AgentLoop` 把「用户消息 + 工具协议段」发给模型，模型输出里若出现 `/$TOOL:工具名 PARAMS:{json}` 就解析成工具调用；只读工具直接执行，写/危险级先挂起等审批；结果回灌给模型，进入下一轮，最多 10 轮（`agent.max_turns`，可在 `config.json` 调整，范围 1–25）。
- **工具从哪来**：内建方块 + 已加载 MOD/技能注册的工具。内建方块如下（`risk` 决定是否审批）：

  | 工具 | 风险 | 用途 |
  |---|---|---|
  | `list_dir` / `glob` / `grep_text` | read | 目录、通配符、内容搜索 |
  | `file_read` | read | 读文件（`offset` / `limit` 分页） |
  | `web_search` | read | 联网搜索（依赖 `skills/noic.webSearch` 的代码目录） |
  | `skills` | read | 列出/调用已加载的 skill（只放行只读级） |
  | `automation` | read | 查自动化 flow 与运行记录 |
  | `realityCheck` / `areYouUnderTrouble` | read | 输出侧内容审视 / 输入侧危机信号识别，模型可主动调用，MOD 不能停用 |
  | `file_write` / `file_edit` | write | 写文件、局部替换，**需审批** |
  | `automation_trigger` | write | 手动触发 flow，**需审批** |
  | `shell` | dangerous | 执行命令，**需审批**，默认关闭 |

- **参数校验在哪一层**：模型写错参数名或类型时，执行前就会被拦下并回灌一条可指导修正的错误文本（说清缺哪个字段、期望什么类型），不会真的去调工具。
- **`shell` 目前默认关闭，且前端没有开关**：要在 `.simchat/data/config.json` 的 `agent` 段加 `"shell_enabled": true`（可配 `shell_timeout`，默认 10 秒，范围 1–30）。下一次 Agent 运行即生效，无需重启服务。
- **审批策略下拉「审批 · Manual / Auto / Off」目前未实现**：它只改前端本地状态，`run_id`/`decision` 之外的策略参数不会发给后端，因此**选 Auto 也不会自动放行**。写操作仍然逐次弹审批卡。
- **上下文与用量**：每轮推理后会发 `token_usage` 事件，前端据此累加用量条；当估算的 prompt 超过阈值（约 12288 tokens）时，Agent 会把早期的 transcript 合并成一行摘要（不调 LLM），并发 `compacted` 事件——所以你会看到「早期 N 条已合并」的提示，这不是模型失忆。
- **会话隔离**：Agent 会话 id 以 `agent_` 开头，和对话会话分开存放，切模式不会把两边的上下文混在一起。
- **一个容易误解的行为**：即使你把开关留在「对话」，只要当前激活的实例 `agent_capable=true`，`/api/chat` 后端也会走 ReAct 循环（10 轮上限、`shell` 关闭）。这是历史行为，不是 bug；想纯聊天就取消激活实例，或把实例的「允许 Agent 模式」关掉。

## 5. 常见坑

- **Agent 一直不调用工具**：模型太小或工具的 `usage` 描述它没看懂。换更强的模型，或直接把工具名说进任务里（「用 glob 找…」）。
- **审批卡片出现后界面像卡住了**：这是设计如此——流已经断开，等你点批准/拒绝后前端用同一个 `run_id` 续跑。不要刷新页面，刷新会丢掉这次挂起（挂起态有 TTL，默认 600 秒）。
- **提示「shell 工具未启用」**：配置文件没开 `shell_enabled`。见上节。
- **写操作被拒绝后 Agent 反复重试**：在任务里明确「不要写文件，只给方案」，或直接点停止。

## 6. 验收清单

- [ ] 能创建一个实例，并说出「允许该实例以 Agent 模式运行」的作用
- [ ] 能激活实例，切换「对话 / Agent」开关
- [ ] 跑通一次需要读文件的任务，看到工具调用时间线
- [ ] 触发一次写操作审批，并分别试过批准与拒绝

已知限制：审批策略下拉目前不生效、`shell` 需要手工开启，见 [known-limitations.md](../known-limitations.md)。
