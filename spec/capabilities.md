# Capability 权限模型（v1 草稿）

> 原则：**默认无权限、显式声明、本体强制、无法被 MOD 覆盖。**
> 权限检查发生在本体侧（加载器 + 工具执行器 + 调度器），不是“MOD 自觉遵守”。

## 1. 权限清单

| capability | 值 | 授予的能力 | 本体强制点 | 用户可见性 |
|---|---|---|---|---|
| `fs.read` | `["workspace", "mod-data", "docs/"]` | 读取指定作用域内文件 | 路径解析器（同 `safe_resolve` 语义：拒绝绝对路径与 `..`） | 安装时列出 |
| `fs.write` | 同上 | 写入指定作用域 | 同上 + **逐次审批** | 每次弹审批卡 |
| `net` | `{"domains": ["api.example.com"]}` | 发起出站 HTTP | 出口代理白名单；不在名单内直接失败 | 安装时列出域名 |
| `shell` | `true` | 调用宿主 shell | 命令黑名单 + 超时 + cwd 限定 + **逐次审批**；本体设置关闭时 MOD 声明无效 | 每次审批 |
| `process` | `true` | 以子进程运行 MOD 代码 | 独立进程 + 受限环境变量 + 资源上限 | 安装时提示 |
| `credentials` | `["openai.api_key"]` | 获取凭据**句柄** | 凭据由本体保管，MOD 只拿到引用；日志脱敏 | 安装时列出名称 |
| `schedule` | `true` | 注册 cron / 事件触发 | 调度器配额 + 审计 + 全局开关 | 安装时提示 |

**未列出的能力一律不可用。** 未知 capability 字段 = manifest 校验失败 = 拒绝加载（不是忽略）。

## 2. 作用域（scope）语义

- `workspace`：本体的工作目录（Agent 的 `workdir`）。
- `mod-data`：该 MOD 自己的数据目录（`mods/<id>/data/`），可写，不与其他 MOD 共享。
- `docs/`：相对 workspace 的子路径。**不允许** `..`、盘符、`~`、UNC 路径。
- 绝对路径一律拒绝，包括“用户自己选的目录”——需要绝对访问时由本体弹目录选择器并把结果作为 scope 注入，而不是让 MOD 自己拼路径。

## 3. 信任等级

| 等级 | 适用 | 校验 | 权限上限 |
|---|---|---|---|
| `community` | 无签名或签名不可信 | schema + 静态扫描 + 人工审核（首次） | 全部能力需用户逐项同意 |
| `verified` | 已验证发布者签名 | 签名 + 哈希 + 复审 | 可预授权 `fs.read` / `net` |
| `first-party` | 官方签名（binary） | 官方密钥 + 完整性 | 可预授权；仍不能关闭安全闸门 |

`verified` 不是“免审批”：`fs.write` / `shell` 永远逐次确认。

## 4. 安全闸门：永远在本体

以下能力**不开放为 MOD**，也不存在对应的 capability：

- 内容安全检测与拒绝（MOD 只能追加规则，不能移除或短路本体规则）
- 审批流程本身（不能替用户点“同意”）
- 审计日志与配额（不能写入、不能清空）
- 吊销列表检查
- 加载器自身的完整性校验

> 判定标准：如果“恶意 MOD 拥有它就能让平台失效”，它就必须在本体。

## 5. 冲突与失败语义

| 情况 | 行为 |
|---|---|
| 声明了 capability 但运行时未使用 | 允许（最小权限仍按声明授予，不做动态提权） |
| 运行时越权访问 | 立即失败，记审计，连续 3 次自动禁用该 MOD |
| 两个 MOD 声明同一 hook 且互斥 | 加载器按 manifest 的 `priority`（后续版本加入）或安装顺序择一，冲突需用户裁决 |
| 本体升级导致 capability 语义变化 | 必须走 ABI major 版本；旧 MOD 标记为“需更新”，不静默运行 |
| 用户关闭某能力 | 该 MOD 降级运行或自动禁用；不静默忽略调用 |

## 6. 与现状的差距

当前代码里权限是“全有或全无”：

- 工具直接 `import` 进 `TOOL_REGISTRY`，没有声明面（`tools.py L605-L625`）。
- shell 只有全局开关 `_shell_config`（`tools.py L56-L67`），按进程生效，不区分调用方。
- 文件沙箱只锚定 `workdir`，无法表达“只读某个子目录”或“MOD 私有数据区”。

Phase 2 的加载器必须把上述三点改为**按 MOD 注入的 capability 上下文**，而不是全局变量。
